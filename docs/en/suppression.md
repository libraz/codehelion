# Suppression

A duplication report is only useful if what is in it is worth reading. Suppression
is how the code a project does not maintain, does not write by hand, or cannot
unify stops crowding out the rest.

Every classification is recorded whatever the policy does with it, so
`--show-suppressed` lists the hidden groups with the reason each was hidden, and
JSON and SARIF retain suppressed findings regardless of the flag.

> **Pre-1.0 surface.** The defaults are part of what Structural mode reports and
> are measured with it. The configuration keys that change them are documented
> and tested, but have not had the real use that would make them worth a
> promise, so they can change between releases.

## The three dispositions

Most policies take one of three values:

- `hide` — the group is not listed.
- `rank-down` — the group is listed below behavioural duplication.
- `report` — the group keeps its measured priority.

`rank-down` is the default wherever the classification is a strong hint rather
than a certainty: the group is still there for a reader who scrolls, and it is not
in the way of one who does not.

## By path

```toml
[suppression]
# paths = []                        # path globs to hide
# vendored-paths = [...]            # trees the project vendors rather than writes
```

`vendored-paths` ships with the conventional set — `third_party`, `vendor`,
`external`, `deps`, `subprojects`, `node_modules`, `.venv` and their variants —
and hiding them is on by default, because duplication inside a dependency is not
this project's to remove. Setting the key replaces the defaults; setting it to
`[]` reads vendored code like any other. `--include-vendored` undoes it for one
run.

Duplication spanning a vendored tree and the project's own code stays visible
either way. That holds for every rule here: a group is hidden only when *every*
occurrence in it is.

## By enclosing name

```toml
# symbols = []                      # globs over the name of the enclosing unit
```

Matched against the name of the unit an occurrence sits in, which is the way to
quiet one generated accessor family without hiding a whole file.

## Generated code

```toml
# generated-markers = ["@generated", "do not edit", "automatically generated", "auto-generated", "autogenerated"]
```

A file whose first lines carry one of these banners is machine output, and its
duplication is the generator's rather than a maintenance problem. Matching
ignores case. Setting the key replaces the defaults, so a project adding its own
generator's banner lists these alongside it.

## Test code

```toml
# test-paths = ["**/tests/**", "**/test/**", "**/__tests__/**", "**/*_test.*", "**/*_tests.*", "**/test_*.*", "**/*_spec.*"]
# test-code = "rank-down"
```

Test code repeats itself by design: twenty cases that differ in one argument are
a suite, not a duplication to unify. Path evidence is combined with source
evidence — a Rust test attribute, a C or C++ framework case macro — and a Rust
module the crate declares as test-only counts wherever it is written, including
files it is split across.

A group spanning both a suite and the code it exercises is not test code, and is
not classified as such.

## Boilerplate shapes

```toml
[suppression.boilerplate]
# trivial-body = "rank-down"
# forwarding = "hide"
# macro-repetition = "rank-down"
# guarded-dispatch = "hide"
# configured-answer = "hide"
# composed-answer = "hide"
# built-answer = "hide"
```

These name shapes rather than files: a body that forwards to one call, a match arm
that returns a constant, a dispatch guarded by one condition. Unifying them
usually costs more than it saves, and reporting them buries what does not.

`--include-trivial` restores trivially-shaped predicate groups to their measured
priority for one run, which is what an explicit review of the predicate families
wants.

## Integer-width families

```toml
# width-family = "hide"
```

One routine per integer width is often what a typed language requires, so these
are hidden by default. Set this to `report` where a macro, generic or template
could express the family once.

## Degenerate repetition

```toml
# entropy-ratio-floor = 0.60
```

A group below this normalized content-entropy ratio is marked as degenerate
repetition — the same few tokens repeating rather than a routine. The value is
relative to the largest entropy a group of the same token length can carry, so it
does not turn clone length into a noise filter.

## By id

```toml
# clone-ids = []
```

A specific group, named by its stable id, for the case where a project has decided
about that one duplication and nothing more general describes it. An id describes
one group's content, so it stops matching once that content changes — which is
the intended behaviour: the decision was about the code as it was.

For a decision that should survive the code changing, use a
[baseline](baselines.md) instead.

## Modes

These classifications need the parsed shape, so Structural and Semantic scans
apply them and Fast scans say explicitly that they are unavailable. That is the
main reason a Fast report on a large tree is longer than it is useful. See
[Analysis modes](analysis-modes.md).
